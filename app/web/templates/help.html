Windows 日次運用

通常（自動起動を設定済みなら）: Windows にログオン → 45〜60秒待つ → マーケットスピードII にログイン。以上。

手動で起動/停止したいとき（PowerShell）:

cd $HOME\mss2-trader
git pull
.\bridge\run_all.ps1        # backend → Excel(RSS) → bridge を一括起動
.\bridge\stop_all.ps1       # 停止（Excel は手動で閉じる）

自動起動の登録/解除（スタートアップフォルダに登録・管理者権限不要）:

.\bridge\install_autostart.ps1            # 登録
.\bridge\install_autostart.ps1 -Uninstall # 解除

ログの確認:

Get-Content .\logs\backend-$(Get-Date -Format yyyyMMdd).log -Tail 30
Get-Content .\logs\bridge-$(Get-Date -Format yyyyMMdd).log -Tail 30

初回だけ Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned を実行すると .\xxx.ps1 の直接実行ができるようになる（管理者不要）。

トラブルシューティング

症状対処
ダッシュボードの「ブリッジ状態」が遅延 時間外（寄り付き前・引け後・週末）なら正常な場合が多い。場中に出るなら:
1. bridge ログを確認（sent N quotes が続いているか）
2. .venv\Scripts\python bridge\bridge.py --dump で Excel の生値を確認（ #NAME? や空なら MarketSpeed II のログイン切れ）
3. 直らなければ stop_all.ps1 → Excel を閉じてMS2に再ログイン → run_all.ps1
ページで Internal Server Error logs\backend-*.log の末尾（Traceback 行以降）を確認。 コード更新（git pull）した直後は必ず stop_all.ps1 → run_all.ps1 でバックエンドを再起動する（新しいテーブル等は再起動時に作られる）
backend / bridge が重複して起動している Get-CimInstance Win32_Process -Filter "Name = 'python.exe'" | Select ProcessId, CommandLine で確認し、stop_all.ps1 で一旦全部止めてから run_all.ps1 を実行し直す

過去データの取得

Yahoo Finance（yfinance）から過去足を取ってきて DB に保存する。ネットがあれば RSS 無しでも使える。 /data 画面の「過去データを取得」フォームから直接実行できる （「候補から反映」で取り込み中の銘柄や戦略の対象銘柄をコード欄に入れられる）。CLI からも同じことができる:

.venv\Scripts\python scripts\fetch_history.py 7203 --interval 5m --period 60d
.venv\Scripts\python scripts\fetch_history.py 7203 6501 9984 --interval 5m --period 60d
.venv\Scripts\python scripts\fetch_history.py 7203 --interval 1d --period 2y
interval取得可能な期間の目安
1m直近7日ほど
5m / 15m直近60日ほど
1d長期間OK（2y 等）

コードは自動で .T を付けて照会（日本株前提）。取得した足は データ、 バックテスト、最適化 の対象になる。

バックテスト

/backtest で戦略・銘柄・足・パラメータ・手数料を指定して実行。 戦略を選ぶと、下の「パラメータ」欄にその戦略の項目が名前・説明付きで自動で並ぶ （JSONを手で書く必要はない。マウスを乗せると説明が出る項目もある）。 細かく直接編集したい場合は「JSON で直接編集」を開けば生のJSONも編集できる。 結果は取引数・勝率・合計損益・PF・最大DDと、往復トレード一覧。過去分は 履歴 から見返せる。用語の意味は下の用語集参照。

最適化（パラメータ探索）

/optimize はパラメータの組み合わせを総当たりでバックテストし、 提案する機能。

  1. 戦略・銘柄・足を選ぶ
  2. 「パラメータ範囲」の各項目に、探索したい値をカンマ区切りで入れる。例: 短期期間の欄に 5,10,15 → その3値を総当たり。1つの値のままなら固定
  3. 学習期間の割合（既定0.7 = 前半70%で探索）、ランキング指標（合計損益/PF/勝率/平均損益）を指定して実行

結果の見方が重要: ランキングは 検証期間（探索に使っていない後半のデータ）の成績 で決まる。同じ期間の成績だけで選ぶと過学習（その期間にだけ都合よく合わせた設定）になりやすいため。 検証期間の取引が少ない行には ⚠ が付く — 信用しないこと。良さそうな行の「戦略登録」ボタンから そのパラメータのまま 戦略 に登録できる。過去の探索結果は 履歴 から見返せる。

戦略

作れるロジックはトレンドフォロー・逆張り・ブレイクアウトなど7種類（on_bar() を実装するだけで 自作も可能。詳しくはリポジトリの app/strategy/README.md）。

戦略系統概要
SMAクロストレンドフォロー短期/長期SMAのゴールデン/デッドクロス
移動平均+RSIトレンドフォロー終値とMAの関係 + 傾き + RSI帯でエントリー
トレンド×RSI出戻りアラート専用短期MA/中期MAの上下 × RSIの40/60出戻りで通知（notify向け）

ボリンジャー逆張り逆張り下限バンド反発で買い、中心線/上限で手仕舞い
ドンチャンブレイクアウトブレイクアウトN本高値ブレイクで買い、M本安値割れで手仕舞い

登録は /strategies から。モードは notify（通知のみ）/ paper（擬似約定して成績に反映）/ live（実発注。自動売買で発注許可を ON にしない限り発注されない）。

損切り / 利確

パラメータ欄の一番下に 損切り(%) ・ 利確(%) が全戦略共通で出る （/backtest /strategies /optimize どこでも）。建値からその% 動いたら、戦略ロジック（on_bar()）の判断より優先してその足の高値/安値で 成行手仕舞いする。空欄なら無効（今までどおり戦略自身の判断だけで手仕舞い）。同じ足で両方のライン に達したら損切りを優先する。/optimize でもカンマ区切りで範囲指定して一緒に最適化できる （例: 損切り欄に 2,3,5）。

売買方向（空売り） / 取引区分

全戦略共通の 売買方向（direction）で、long=買いのみ（既定・従来どおり）/ short=売りのみ / both=両方 を選ぶ。売りは買いと上下対称な条件で売建 （ショート）する（例: SMAクロスならデッドクロスで売建、ゴールデンクロスで買戻し）。 同じ銘柄に「買いのみ」と「売りのみ」の戦略を別々に登録して運用することもできる（建玉・注文は戦略ごとに管理。 信用の返済は買建/売建で区別される。日次損失リミットは全戦略の合計で判定）。 バックテスト・ペーパーでは売建の損益（下がれば利益）・損切り/利確（上がったら損切り）・大引け手仕舞いが すべて反映される。信用の金利・貸株料は含まない。

取引区分（trade_type）は実発注の注文種別で、現物か信用 （大引けをまたがない戦略はいちにち信用、またぐ戦略は一般信用・無期限）。空売りの実発注は信用のときだけ。⚠ 信用の実発注は実弾で未検証。 返済は Excel の建玉一覧から「銘柄・売買・信用区分・口座区分・建日（bot が建てた日）」が一致する建玉を選ぶので、 bot と同じ日に同じ銘柄・同じ信用区分で手動の建玉を作らないこと（区別できず返済に使われうる）。

大引けをまたぐ（デイトレ設定）

同じく全戦略共通の 大引けをまたぐ のチェックを外すと、日中足（1m / 5m / 15m）では 15:20 までに確定する最後の足（5分足なら 15:15〜15:20 の足）の終値で成行手仕舞いし、 その足では新規買いもしない（建玉を翌日に持ち越さない）。損切り/利確に達していればそちらが優先。 既定はチェックあり（従来どおり持ち越す）。日足では無視される。バックテストでは「次の足が別の日」の足も 大引けとみなす（15:00 引けだった 2024/11 以前のデータ用）。live では前日から持ち越してしまった建玉 （大引け時に backend が止まっていた等）を翌日最初の足で手仕舞いする。/optimize では true,false と入れれば両方を比較できる。

自動売買 / 実発注（mode=live）

⚠ 実弾（MarketSpeed II の発注機能 ON）では未検証の機能（発注機能 OFF で 「発注ロック中」→ rejected になるところまでは実機確認済み）。試す前に bridge/README.mdの「実発注（P4）」の安全な確認手順を必ず読むこと。

戦略を mode=live で登録・有効化しても、それだけでは発注されない。以下が すべてtrue でないと発注しない（二重・三重の安全弁）:

  1. config/config.toml の [trading] enabled = true（要編集+再起動）
  2. 自動売買 › 概要で発注許可が ON（旧称 ARMED。backend 再起動で自動的に OFF に戻る）
  3. 取引時間内（JST）・数量/金額が上限内・日次損失リミット未達（config.trading の各種上限）
  4. 足の確定から max_signal_age_sec（既定120秒）以内のシグナルであること（backend 停止後に まとめて評価された古い足のシグナルは「発注見送り: 古い足のシグナル」として記録だけする）
  5. 同一銘柄で決着待ちの注文が残っていない（二重発注防止）

発注の実体は非同期のリレー: backend が発注キューを作る → bridge が拾って Excel の RssStockOrder に書き込み・ 発注トリガーを立てる → セルの表示が確定するまで待つ → 結果を backend に報告、という流れ。 セットアップ手順・既知の制限（成行のみ、約定の自動確認は未実装 等）は bridge/README.md を参照。

自動売買の概要で発注許可の状態・本日の損益・建玉、発注履歴タブで注文（状態・ エラー内容）が確認できる。

通知の設定（Slack / メール）

config\config.toml の [notify] を設定して dry_run = false にすると、liveエンジンが出したシグナルが実際に届く。未設定・dry_run = true のときは 送信せずログ出力のみ（[notify dry_run] ...）。両方設定すれば両方に送る。

  • Slack: slack_webhook_url に Incoming Webhook URL
  • メール（Gmail）: email_to（送信先）・smtp_user（送信元の Gmail アドレス）・ smtp_password（Google アカウントのアプリ パスワード。2段階認証を有効にしてから 発行する16文字。通常のログインパスワードは使えない）の3つを入れる
